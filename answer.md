Med vattenfallsmetoden så planerar man projektet i förväg och gör allt i en specifik och fast ordning, de vill säga att allt flödar åt samma håll som ett vattenfall. Medans Agil metodik delar man in det i korta intervaller, där man planerar, utvecklar, testar och leverar ut lite av produkten succesivt. Man justerar projektet under tidens gång. Man ska använda vattenfallsmetoden när man har tydliga och strukturerade projekt, där ändringar kan bli kostasamma om de börjar krångla till exempel i medicin branchsen.
En git-commit är en snapshot tillsammans med ett meddelande som man skriver vilken ändring man gjort. Varje commit får en eget unik id de vill säga (hash), de gör att man kan gå tillbaka och se det i historiken, och se koden och hur man utvecklade sidan steg för steg. Tänk dig att din app kraschar och du inte har en aning vad som gått fel, då måste du leta rätt manuellt vart och när koden krashade. Men med Git kan du kolla historiken med git log eller git revert och ångra felet, utan att det andra arbetet du gjort går förlorat. 
Sammarbete i GitHub gör de möjligt att flera personer (utvecklare) kan arbeta på samma projekt samtidigt. Branch är som en kopia av av (main) där man kan jobba ostört och fixa och lägga till utan att påverka koden i (main), flera personer kan även jobba med sina egna branch. Sen kan man göra en pull request som man sedan kan merga till (main) pull requesten visar också vilka ändringar man gjort som någon kan granska så allt ser bra ut, och sen godkänna ändringen. Ser ändirngen inte bra ut kan den som gör granskningen skicka tillbaka med en kommentar, vad som inte ser bra ut. Sen kommer vi till merge om de ser bra ut, de är sammanslagningen av branchen till oftast main, och då blir koden i branch en del av main.
